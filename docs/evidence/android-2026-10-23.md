# Anyomi Android audio + release evidence — 2026-10-23

Device: headless Android emulator (`anyomi`), Android 15 / API 35, x86_64.
Engine: `ap0dl-core` 2.2.0 through `crates/ap0dl-mobile` JNI.

## Sub/Dub switching (Re:Anime, Frieren E1, 1080p)

Fresh install defaults to **Sub**. With the player controls visible, the audio
sheet reported:

```text
Audio
Choose the version you want. The source is re-resolved for your pick.
Active player track: Japanese
Sub    Original audio · subtitles
Dub    Dubbed audio
```

Selecting **Dub** re-resolved the stream at 1080p, preserved the current
position and reported:

```text
Active player track: English
```

Selecting **Sub** again preserved the position and reported:

```text
Active player track: Japanese
```

The preference is persisted (debug build shared preferences contained
`audio_preference = dub`, then `sub` after switching back). The `AUDIO` chip
reflects the selection and turns amber when the source cannot honour it.

## Fallback when a source lacks the chosen version

AnimeParadise (Sub only) was opened with the persisted default set to Dub. The
player kept working, the chip showed an amber `SUB`, and the audio sheet said:

```text
Dub audio is not offered by this source.
Playback is using Sub so the episode still works.
```

AnimeGG's tested episode only exposed a Dub source while the default was Sub. It
showed the symmetric warning and `Active player track: English`.

## Download audio routing

Default audio: Sub. Re:Anime Frieren E1 downloaded from the details screen. The
Downloads tab showed:

```text
Sousou no Frieren
Episode 1 · Sub
Re:Anime
HLS segment 255 of 260 · 98%
1 EPISODES · 1.0 GB
```

The completed card showed the 1.0 GB file as `Available offline` with a Play
action. This confirms the audio preference reaches the Rust download bridge,
the progress callback drives the UI, and the file lands in app-private storage.
The final minified release build repeated the same flow: the active card read
`Episode 1 · Sub`, progressed through 122/260 HLS segments, and completed as a
1.0 GB offline file.

## AnimeToki / AT-Cloud quota

Direct probes of the tested Frieren files returned a Cloudflare-hosted page:

```text
<title>Download Limit Reached | AnimeToki</title>
The AT-Cloud Drive quota for this file has been exceeded due to high traffic.
Suggestion: Please wait a few hours or try again later. Quotas reset automatically.
```

This is a per-file CDN quota, not an auth or range-parser failure. The 1 KiB
probe used by the first proxy draft passed while the real stream was blocked, so
`RangeProxy` now probes 1 MiB, caches that prefix for the first response, and
detects the quota page. Playback now fails before the player starts with:

```text
cloud.animetoki.com has exhausted its download quota for this file;
try another episode or source, or wait for the quota to reset
```

AnimeToki remains registered (catalogue, details and episode indexing are live)
but is marked **experimental**; no playback success is claimed while AT-Cloud
quotas are exhausted for the tested files.

## Limitations

- Dual-audio single-file track selection prefers `ja` for Sub and `en` for Dub
  through ExoPlayer. It depends on the file carrying language metadata; the
  player settings gear still exposes all embedded tracks.
- AnimeToki availability depends on AT-Cloud's per-file quota.
- The release APK is debug-key signed for direct installation, not Play Store
  distribution.
